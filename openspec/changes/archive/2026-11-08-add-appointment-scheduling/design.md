## Context

Cabinet Nour El Islam currently tracks completed patient sessions (`session`) and therapy plans (`therapyPlan`), both of which immediately affect financial totals (`patient.totalCost` and `payment` ledger). There is no mechanism to organize future patient bookings, handle phone bookings from unregistered walk-in callers, or visualize daily, weekly, and monthly clinic schedules across the Host and Client workstations on the LAN.

## Goals / Non-Goals

**Goals:**
- Provide a dedicated `Rendez-vous` navigation tab accessible to both `Admin` and `Employé` users.
- Support booking appointments for registered patients (`patientId`) as well as walk-in/phone callers (`guestName`, `guestPhone`) with a one-click patient creation shortcut.
- Provide three synchronized schedule views in a single tab:
  - **Daily View (`Jour`)**: Chronological table with quick status buttons (`Prévu` → `Confirmé` → `Terminé`, `Annulé`, `Absent`), conflict indicator, walk-in registration shortcut, and one-click session conversion.
  - **Weekly View (`Semaine`)**: 7-day column layout with appointment cards per day and visual distinction for non-working days.
  - **Monthly View (`Mois`)**: Calendar grid showing daily appointment count badges that navigate to the Daily view when clicked.
- Store configurable clinic working days, opening/closing hours, and default appointment duration in the shared H2 database (`clinic_settings`) so all LAN workstations share the same schedule rules.
- Warn (without blocking) when an appointment overlaps another active appointment on the same date and practitioner (or clinic-wide if no practitioner is assigned).
- Provide a one-click "Convertir en séance" workflow that pre-fills `SessionFormController` with the patient and `motif`, links the resulting `sessionId` on the appointment, and ensures appointments themselves never alter `patient.totalCost` or the payment ledger.
- Display the patient's next upcoming appointment ("Prochain RDV") and a "+ Programmer RDV" button inside `patient_detail.fxml`.

**Non-Goals:**
- Visual drag-and-drop hour-by-hour timeline grid in the initial Daily view (a chronological table is faster for receptionists and simpler in JavaFX).
- Automated SMS/WhatsApp external reminders.
- Affecting financial balances or cash drawers prior to explicit conversion into a `Session`.

## Decisions

### 1. Database Schema (`appointment` and `clinic_settings`)
- **`appointment` Table**:
  ```sql
  CREATE TABLE IF NOT EXISTS appointment (
      id           INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      patientId    INTEGER REFERENCES patient(id) ON DELETE CASCADE,
      guestName    TEXT,
      guestPhone   TEXT,
      workerId     INTEGER REFERENCES worker(id) ON DELETE SET NULL,
      date         TEXT NOT NULL,          -- 'yyyy-MM-dd'
      startTime    TEXT NOT NULL,          -- 'HH:mm'
      durationMin  INTEGER NOT NULL DEFAULT 30,
      motif        TEXT,
      status       VARCHAR(20) NOT NULL DEFAULT 'PREVU',
      sessionId    INTEGER REFERENCES session(id) ON DELETE SET NULL,
      createdBy    VARCHAR(50) NOT NULL,
      createdAt    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
  );
  ```
  - **Rationale**: Nullable `patientId` paired with `guestName`/`guestPhone` allows immediate phone booking without polluting the `patient` table until the caller actually arrives or is explicitly registered. Nullable `workerId` (`ON DELETE SET NULL`) keeps practitioner assignment optional. Nullable `sessionId` (`ON DELETE SET NULL`) prevents double conversion into a `Session` while automatically unlocking re-conversion if the linked session is later deleted.
  - **Indexes**: `idx_appointment_date ON appointment(date)`, `idx_appointment_patientId ON appointment(patientId)`, and `idx_appointment_sessionId ON appointment(sessionId)` for fast LAN queries across daily, weekly, and monthly date ranges.

- **`clinic_settings` Table**:
  ```sql
  CREATE TABLE IF NOT EXISTS clinic_settings (
      settingKey   VARCHAR(64) PRIMARY KEY,
      settingValue TEXT NOT NULL
  );
  ```
  - **Default keys seeded in `DatabaseInitializer`**:
    - `schedule.working_days` = `"SAT,SUN,MON,TUE,WED,THU"` (Friday off by default, configurable via UI).
    - `schedule.start_time` = `"08:00"`
    - `schedule.end_time` = `"17:00"`
    - `schedule.default_duration_min` = `"30"`
  - **Rationale**: Unlike `~/clinic/config.properties` which is workstation-local (storing `HOST` vs `CLIENT` role), storing schedule settings in H2 ensures that changes made on the Host or Client immediately apply to all workstations on the LAN and are preserved in `.cni` backups.

### 2. Overlap Conflict Detection (Warn, Do Not Block)
- Two appointments on the same `date` overlap when both have an active status (`PREVU`, `CONFIRME`, or `TERMINE`—excluding `ANNULE` and `ABSENT`), their time intervals `[startMin, startMin + durationMin)` intersect (`startA < endB && startB < endA`), and either:
  - Both specify the same `workerId`, or
  - At least one of them has `workerId IS NULL` (clinic-wide slot).
- **Rationale**: In rehabilitation clinics, therapists frequently overlap patients intentionally (e.g., electrotherapy + manual therapy) or squeeze in urgent consultations. Therefore, `AppointmentFormController` queries `AppointmentDAO.findOverlappingAppointments(...)` on save and shows a `CONFIRMATION` dialog listing the conflicting appointment(s) so the receptionist can confirm or adjust the time.

### 3. Walk-in to Registered Patient & "Convertir en Séance" Flow
- When an appointment is booked as a walk-in (`patientId IS NULL`):
  1. The Daily view displays an `"Invité"` badge next to `guestName` and provides a `"Créer patient"` action that opens `patient_form.fxml` pre-populated with `guestName` and `guestPhone`, saves the new `Patient`, and updates `appointment.patientId = newPatient.getId()`.
  2. If the user clicks **"Convertir en séance"** on a walk-in appointment whose `patientId` is still `NULL`, the controller first opens `patient_form.fxml` (pre-filled with `guestName` and `guestPhone`) or creates the patient record, links `appointment.patientId`, and then opens `session_form.fxml`.
- When `SessionFormController` opens from an appointment:
  - A new helper `setPrefillFromAppointment( int patientId, String date, String motif )` pre-selects the patient, sets the session date (defaulting to `LocalDate.now()` or the appointment date), and pre-fills `treatmentArea` with `motif`.
  - Once the user saves the session, `SessionDAO.addSession(...)` generates the new `session.id`, and `AppointmentDAO.markConvertedToSession(appointmentId, session.getId())` sets `sessionId = session.getId()` and `status = 'TERMINE'`.

### 4. View Architecture (`RendezVousController` implementing `Refreshable`)
- `RendezVousController` uses a view-mode toggle (`JOUR`, `SEMAINE`, `MOIS`) with a shared date navigation bar (`◀`, current period label, `▶`, `Aujourd'hui`, Practitioner filter, Status filter, `+ Nouveau RDV`, `⚙ Horaires`):
  - **Daily View**: A `TableView<Appointment>` sorted by `startTime ASC` with columns for Time & Duration (with `⚠️` overlap indicator and off-hours note), Patient/Guest (with `Inscrit` / `Invité` badge), Phone, Practitioner, Motif, Status badge, and inline Action buttons (`Confirmer`, `Convertir en séance`, `Absent`, `Annuler`, `Modifier`).
  - **Weekly View**: A 7-column `GridPane` (starting Saturday or Monday based on working days, defaulting to `Sam – Ven` for Algerian clinics) where each day column has a header (clicking jumps to Daily view) and a scrollable `VBox` of compact appointment cards. Non-working days (e.g., Friday) are visually muted.
  - **Monthly View**: A 7×6 `GridPane` calendar. Each day cell shows the day number and summary count pills (`X prévus`, `Y terminés`) loaded via a single date-range query `AppointmentDAO.getAppointmentsByDateRange(startDate, endDate)`. Clicking a day cell switches the active mode to `JOUR` for that date.

## Risks / Trade-offs

- **[Risk] Walk-in duplicate patient creation** → **Mitigation**: In `AppointmentFormController`, reuse the debounced patient search autocomplete so the receptionist immediately sees existing patients matching the typed name or phone number before choosing walk-in mode.
- **[Risk] Stale schedule view on LAN when multiple receptionists book simultaneously** → **Mitigation**: `RendezVousController` implements `Refreshable` (reloading on tab switch) and reloads immediately after any modal action; a manual refresh button is also provided in the toolbar.
- **[Risk] Backup/Restore compatibility with new tables** → **Mitigation**: `DatabaseInitializer.initializeDatabase()` uses `CREATE TABLE IF NOT EXISTS` for `appointment` and `clinic_settings`, and `DatabaseMigrator` safely handles legacy imports even when those tables do not exist in older `.sql`/`.db` files.
